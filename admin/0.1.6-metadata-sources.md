## Endpoints y fallos

TMDB utiliza `/movie/{id}` o `/tv/{id}` y `/tv/{id}/season/{number}`, con el `language` solicitado. Estos endpoints ya son compatibles con el relay existente, sin nuevos parámetros ni cambios de Worker. Los mismos códigos ISO de idioma de TMDB se introducen en la pantalla (por ejemplo `en-US`, `es-MX`, `es-ES`, `pt-BR`). No se usa traducción automática ni se asegura que la fuente tenga traducción: la vista dice idioma solicitado y posible texto original. Con un `tmdb_id` existente se utiliza esa identidad; sin él se presentan resultados de la búsqueda existente para elección manual. Las recuperaciones no vinculan ni reemplazan IDs del catálogo.

TVmaze utiliza `/lookup/shows?imdb=…` cuando existe IMDb válido; verifica la identidad externa devuelta. Si no hay coincidencia, utiliza `/search/shows?q=…`. Todos los candidatos, incluso una coincidencia única, se presentan con título, año, fuente, ID y enlace para confirmación. No se usa `singlesearch` ambiguo. Al comparar consulta `/shows/{id}`, `/shows/{id}/episodes?specials=1`, las fichas opcionales `/shows/{id}/seasons` y las imágenes opcionales `/shows/{id}/images` (sólo referencias URL, sin descargar binarios al catálogo). Se ofrecen nombres, descripciones, carátulas de temporada y fondos únicamente si esos endpoints los devuelven válidos.

El cliente TVmaze no envía Authorization y mantiene un User-Agent identificable. Limita globalmente sus instancias a una solicitud cada 600 ms, bajo el umbral documentado de al menos 20/10 segundos por IP. Pauta las llamadas de una operación explícita con una espera acotada, revisando cancelación. HTTP 429 establece un enfriamiento de 2–60 segundos y se informa, sin bucle de reintentos automáticos. Un 404 de búsqueda externa permite buscar candidatos por nombre. La redirección del lookup sólo se acepta al mismo origen y a `/shows/{id}`; no se envían datos a destinos arbitrarios.

Timeout por llamada de 25 segundos y respuesta TVmaze limitada a 5 MB. Los fallos de consultas necesarias impiden aplicar un resultado incompleto. Si falla una ficha opcional de temporada/fondo, se muestra la advertencia y no se ofrecen sus campos; 429 o cancelación se propagan. No se registran tokens, sesiones ni cuerpos privados. La cancelación detiene llamadas del proveedor y descarta callbacks tardíos.

## Correspondencia de episodios

- Sólo se trabaja sobre temporadas/episodios ya existentes, identificados de manera única por sus números actuales. No se crea, elimina, reordena o renumera contenido.
- TMDB puede considerarse seguro cuando el ID del episodio existente coincide con el recuperado, ambos son únicos y mantienen temporada/número. Si el ID está repetido, fue movido o es distinto, se excluye.
- Sin ese ID fiable, incluido TVmaze, la coincidencia numérica sólo es una propuesta. El usuario debe marcar **Confirmo que es el mismo episodio y orden**, comprobando que no sea un doble, especial reubicado u otra numeración. Hasta entonces sus campos están bloqueados y desmarcados. Al confirmar, se seleccionan únicamente sus campos faltantes válidos.
- Temporada 0 exige confirmación manual, incluso con TMDB. Los especiales TVmaze sin número no se transforman en episodios regulares ni se asignan a temporada 0 inventada.
- Números ausentes, duplicados o sin contraparte se excluyen con advertencia; no se intenta resolver órdenes alternativos por posición, proximidad ni duración. No hay selector para reasignar una numeración diferente en esta versión: esos episodios quedan excluidos.
- Se pueden elegir como máximo 20 temporadas por operación TMDB. Una consulta de ficha general sin temporadas no agrega capítulos.

## Campos y esquema compartido

| Ámbito | Campos permitidos, sólo si válidos/diferentes |
|---|---|
| Película/serie/anime | `titulo`, `sinopsis`, `poster_url`, `backdrop_url`; `duracion` de película si TMDB la devuelve |
| Temporada existente | `nombre`, `sinopsis`, `poster_url` |
| Episodio existente | `titulo`, `sinopsis`, `imagen_url`, `duracion`, `fecha_emision` |

Son los campos que ya utiliza el editor y acepta el parser Mobile existente. Los campos episódicos `sinopsis`, `fecha_emision` e `imagen_url` se conservan según el contrato real del parser, aunque el archivo documental del esquema sea menos detallado. `schema_version` no cambia. No se introduce una nueva propiedad de contenido sin consumidor.

Se reutiliza el objeto existente `fuentes_metadata` para `recuperacion_selectiva`, un registro por ruta con fuente, URL, idioma solicitado/advertido, cambios y licencia cuando corresponda. Es información de procedencia adicional que el JSON completo conserva; no modifica reproducción. No se sobrescriben otras entradas de procedencia. Si la procedencia previa tiene una estructura incompatible se bloquea la aplicación, conservando el original. Los consumidores que redistribuyan los datos deben preservar esos avisos. No se modifican Mobile/Windows para cambiar su presentación.

`backdrop_url` se importa independientemente del alias histórico `fondo_url`: no se cambia un alias que no fue seleccionado. No se recuperan ni vinculan IDs, videos, `telegram_url`, message IDs, `archivo`, `local_path`, `fecha_agregado`, temporadas ni listas de episodios. El guardado mantiene la fecha original o la ausencia histórica de fecha. Títulos genéricos, vacío/espacios, duración inválida y fecha incompleta no se ofrecen como mejoras. Se normaliza HTML con la API Android, entidades, Unicode y espacios; no se concatenan sinopsis ni se traduce texto. Duraciones seleccionadas se serializan en minutos como texto, igual que en el editor manual.

## Reversión e instalación

El respaldo `metadata_undo` queda fuera del catálogo, en el sobre local existente; nunca se publica. Conserva los valores anteriores de la última operación y los propuestos. Se preserva incluso al guardar y reiniciar. Al revertir, sólo se restauran campos de esa operación y su procedencia, preservando ediciones posteriores de otros campos y todas las referencias. Si hubo cambios posteriores en los campos recuperados o su procedencia, no se pisa esa edición. El respaldo permanece si se descarta un borrador de reversión antes de guardarlo. Una recuperación posterior reemplaza el nivel anterior: es una reversión de un nivel, no un historial ilimitado.

No requiere migración masiva. Para instalar la entrega firmada, abrirla sobre la 0.1.5 y elegir **Actualizar**, sin desinstalar ni borrar datos. Se mantiene `ar.com.miflix.admin`; versionCode sube de 6 a 7. La firma debe coincidir exactamente con `C5125975AC14BCD11FFB402158BA112F0E72C92B87DF268B56B77F810CAFD49B`. El informe de entrega documenta las verificaciones criptográficas y resultados de esta compilación.

Prueba Samsung: abrir Frontera Verde existente → Editar → Fuentes → TVmaze → Buscar candidatos → confirmar título/año → comparar temporada 1 → confirmar cada una de las ocho correspondencias → seleccionar sólo títulos y sinopsis deseados (desmarcar cualquier otro campo) → revisar resumen → aplicar → revisar URLs y duración conservadas → Confirmar y guardar → Sincronizar manualmente → actualizar Mobile y comprobar. Primero se puede cancelar en comparación para comprobar que no cambió la ficha. Después, probar revertir desde edición sin sincronizar hasta revisar el resultado. No hubo pruebas en teléfono ni emulador. La confirmación del funcionamiento físico y del despliegue real sigue pendiente. No se modificó el catálogo de producción ni se desplegaron Workers. El informe de entrega distingue los tests automatizados de las consultas HTTP públicas y del replay.
