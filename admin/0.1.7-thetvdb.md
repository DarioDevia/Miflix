## Implementación

`TvdbRecoveryProvider` implementa la interfaz existente. Identifica por `tvdb_id` cuando ya existe (validando identidad), por IMDb verificable mediante lookup oficial, o por búsqueda textual con candidatos manuales. No escribe IDs externos ni el ID interno de MiFlix. Muestra título, año, tipo, fuente, ID y enlace. No elige coincidencias ambiguas automáticamente.

Endpoints API v4 comprobados contra el OpenAPI oficial:

| Operación | Endpoint |
|---|---|
| Autenticar | `POST /login`, JSON `apikey`, `pin` solo cuando se configura |
| Comprobar acceso | `GET /languages` |
| Buscar | `GET /search?query=…&type=movie\|series&limit=50` |
| Lookup IMDb | `GET /search/remoteid/{remoteId}` |
| Identidad existente | `GET /series/{id}` o `/movies/{id}` |
| Detalles | `GET /series/{id}/extended` o `/movies/{id}/extended` |
| Traducción principal | `GET /series/{id}/translations/spa` o `/movies/{id}/translations/spa` |
| Temporada | `GET /seasons/{id}/extended` y `/seasons/{id}/translations/spa` |
| Episodios | `GET /series/{id}/episodes/default?season={n}&page={p}` |
| Traducción episodio | `GET /episodes/{id}/translations/spa` |

Se usa `spa`, código de tres letras de TheTVDB, y se verifica que cada respuesta de traducción declare exactamente ese idioma. No hay traducción por IA ni ML Kit. Una respuesta ausente, vacía o de otro idioma no se reemplaza por inglés. La API documenta una traducción por idioma en este endpoint, sin selector regional es-AR/es-ES; no se inventa esa posibilidad. La opción **Texto base · idioma no verificado** es una consulta separada y todos sus campos quedan desmarcados inicialmente; nunca se etiqueta como español aunque el idioma original de la serie sea español.

Se consultan hasta 20 temporadas ya existentes y solo el orden predeterminado definido por la serie. Se verifican serie, temporada, tipo de orden e ID único; se excluyen órdenes alternativos, episodios sin contraparte, números duplicados, movidos o distintos. Temporada 0 conserva su número y siempre exige confirmación. Cada episodio TheTVDB requiere confirmar manualmente que es el mismo episodio/orden; ninguna confirmación renumera ni crea capítulos. Los casos excluidos requieren corregir la identificación fuera de esta recuperación; no se ofrece una reasignación arbitraria de números.

Solo se aplican rutas permitidas y casillas seleccionadas. El título/sinopsis general, nombre/sinopsis de temporada, título/sinopsis de episodio, duración entera válida y fecha de emisión válida se ofrecen si existen. Las imágenes TheTVDB quedan excluidas por el límite de derechos descrito más abajo: la pantalla lo informa y mantiene las imágenes actuales. Tampoco se copia una duración media de serie como si fuera duración del episodio. El HTML se normaliza conservando Unicode y acentos; se rechazan blancos y nombres genéricos. No se combinan párrafos de proveedores distintos.

Consultar no cambia catálogo ni borrador. **Aplicar datos seleccionados** exige confirmación y aceptación del alcance local, conserva respaldo atómico y modifica únicamente el borrador. Luego se debe **Confirmar y guardar**. Se mantienen el ID interno, números/relaciones, enlaces y referencias Telegram, reproducción, `fecha_agregado`, campos desconocidos y campos no seleccionados. La reversión sigue siendo de un nivel: evita pisar cambios posteriores en los mismos campos y puede sobrevivir guardado/reinicio. Una nueva recuperación sustituye ese nivel de respaldo.

## Configuración, autenticación y seguridad

Configuración → **APIs y proveedores** informa sobre TMDB y TVmaze, permite probar los tres servicios y contiene la API Key de TheTVDB. Entrada oculta con Mostrar/Ocultar, guardar, modificar y eliminar. El PIN se muestra solo si el usuario marca que su modalidad de proyecto sostenido por suscriptores lo requiere; la modalidad gratuita de proyecto con atribución descrita por el propietario usa solo API Key. No se solicita ni se copia un token manualmente.

No se inventa un formato UUID: se acepta una cadena no vacía de hasta 512 caracteres ASCII visibles sin espacios internos/saltos de línea; el servidor valida autenticidad y permisos. El PIN es opcional, máximo 128 caracteres. Las pruebas usan únicamente credenciales sintéticas claramente identificadas.

`SecureTvdbConfig` guarda solo API Key/PIN en `noBackupFilesDir/thetvdb-config.enc`, mediante `AtomicFile`, AES-GCM con IV aleatorio y una clave no exportable de Android Keystore (`miflix-admin-thetvdb-v1`). No depende de bibliotecas Security Crypto obsoletas ni agrega dependencias. No modifica el archivo cifrado del Worker/TMDB ni sus alias. La entrada no usa `rememberSaveable` y la pantalla protege capturas con `FLAG_SECURE`. El catálogo, sus respaldos y la procedencia no contienen API Key, PIN ni token.

`TvdbApi` mantiene el bearer solamente en memoria. Reutiliza la sesión; utiliza `exp` si el token lo incluye como optimización y reautentica una sola vez tras 401. La documentación actual dice un mes, pero el código no fija esa duración ni depende de que siga siendo cierta. No se autentica durante recomposiciones, al abrir Configuración ni al abrir una ficha. Guardar/cambiar/eliminar credenciales invalida el token; cerrar el ViewModel lo descarta. 403 no entra en un ciclo de login; 429 aplica enfriamiento y pide reintentar. Cancelar invalida resultados tardíos y cancela las llamadas.

HTTP directo exclusivamente al host oficial en producción, TLS del sistema, sin redirecciones ni interceptores de logs. Se limita la respuesta a 5 MB y cada consulta a 250 solicitudes, 40 páginas y 2000 registros por temporada. Hay separación de al menos 350 ms entre llamadas; no se atribuye a TheTVDB un límite contractual fijo no documentado. El `Retry-After` de 429 puede prolongar el enfriamiento; no hay reintentos infinitos. Mensajes de error controlados, sin reproducir cuerpos de error, claves, PIN o bearer.

El cifrado protege en reposo; no garantiza secreto absoluto si el dispositivo o el proceso están comprometidos. No se afirma uso de StrongBox ni protección física del hardware sin medir el Samsung. Las pruebas de cifrado/archivo usan JCA con clave inyectada en Robolectric; no sustituyen una prueba de Android Keystore real en el teléfono.

## Condiciones y bloqueo de publicación

Fuentes oficiales consultadas el 27/10/2026:

- API/OpenAPI: https://thetvdb.github.io/v4-api/ y https://github.com/thetvdb/v4-api/blob/main/docs/swagger.yml
- Acceso directo y órdenes: https://github.com/thetvdb/v4-api
- Modalidades y atribución: https://thetvdb.com/api-information y https://thetvdb.com/api-information/signup
- Términos, especialmente sección 2: https://thetvdb.com/tos
- PIN: https://support.thetvdb.com/kb/faq.php?id=82
- Android Keystore: https://developer.android.com/privacy-and-security/keystore

TheTVDB exige atribución con enlace a los usuarios que ven sus metadatos salvo dispensa del proveedor. Sus términos limitan el uso al proyecto autorizado y no conceden redistribución ilimitada ni derechos independientes sobre imágenes/trailers/programación. El README oficial contempla acceso directo bajo la modalidad autorizada del proyecto. No se vio una prohibición técnica que obligue a crear un proxy para este Admin privado; no se creó ninguno.

Work no recibió la API Key ni los términos particulares/estado de aprobación de la cuenta; no certifica que el simple formulario autorice todos los usos. Una prueba de conexión confirma acceso técnico, no licencia de distribución. Se requiere que el propietario mantenga su proyecto y uso autorizados; la aceptación en la comparación solo reconoce ese alcance local y no desbloquea publicación.

La atribución aparece en Configuración, resultados, comparación y revisión; la procedencia de cada campo se guarda en el contenedor existente `fuentes_metadata.recuperacion_selectiva`, con fuente, enlace, idioma, aviso de normalización y `publicacion_bloqueada=true`. No se atribuyen a TheTVDB datos de otros proveedores ni se eliminan créditos TVmaze. El esquema permite esos metadatos adicionales; no se alteró.

Se inspeccionaron sin modificar las pantallas accesibles de Mobile 0.9.13 (`MainActivity.kt`, ref `092ece114c6798d891f50e15808cd0d8250d163f`) y TV 0.1.12 (`TvScreens.kt`, ref `57fca311dc06b5ad9fdcf5a02ac9daa9c08bd0f9`): no se encontró representación de atribución TheTVDB/procedencia. No se verificó el binario instalado de esos clientes.

Por ello, la sincronización de **todo el catálogo** se bloquea antes de cualquier llamada de publicación cuando contiene procedencia TheTVDB. `CatalogRules.publicCopy` también impide producir su JSON para publicación/exportación. Pendientes, catálogo y respaldo quedan intactos al rechazar. Se puede revertir la recuperación y guardar para retirar esos datos; no se filtran o borran silenciosamente campos para publicar el resto. No hay una casilla para saltear la barrera. Catálogos TMDB/TVmaze sin TheTVDB siguen publicando normalmente. La versión base no tiene un exportador de catálogo de usuario separado que deba migrarse; la envoltura local de recuperación sigue siendo privada.

**Dependencia mínima futura:** confirmar por escrito el alcance permitido de la clave para MiFlix y distribución mediante su catálogo; añadir en Mobile y TV un crédito visible y enlace a TheTVDB cuando la ficha/episodio contenga procedencia TheTVDB; conservarla al distribuir. Después, una actualización de Admin podrá retirar la barrera tras verificar esos clientes/permisos. Estos cambios quedan fuera de esta entrega. Las imágenes requieren además los derechos pertinentes. No se necesita cambiar Worker, base de datos ni esquema para la recuperación local; el desbloqueo no se presume autorizado por tener una API Key.

## Instalación y prueba en Samsung

1. Instalá la APK firmada como **Actualizar** sobre 0.1.6. Conserva `ar.com.miflix.admin`, certificado original y code 8. No desinstales ni borres datos. Si Android ofrece una instalación separada o rechaza la actualización, detené el intento y conservá la instalación actual.
2. Inicio → Configuración del servidor → **APIs y proveedores**. Pegá tu API Key. Dejá desmarcada la modalidad con PIN salvo que tu clave sea de proyecto sostenido por suscriptores. Guardá y probá conexión; no ingreses un token. No envíes la clave por chat ni capturas.
3. Si hay 401 revisá clave/PIN/modalidad; si hay 403 revisá aprobación/permisos del proyecto; si hay 429 esperá. La prueba de conexión solo consulta idiomas, no modifica el catálogo.
4. Abrí Frontera Verde existente → Editar → Fuentes → **TheTVDB — Metadatos en español**. Elegí Español (spa), T1, buscá y confirmá título/año/ID. Revisá candidatos y el orden predeterminado.
5. Verificá los ocho pares contra tus publicaciones. Confirmá cada correspondencia segura, seleccioná únicamente títulos/sinopsis necesarios y desmarcá duración/fecha y cualquier dato ya útil. No se ofrecerán imágenes TheTVDB para importar. Anotá el número real de títulos y sinopsis devueltos por API; no presupongas ocho.
6. Revisá el resumen y la advertencia de uso local, aplicá y comprobá enlaces/imágenes/duración/fecha. Guardá solo si querés validar el guardado local. La sincronización quedará bloqueada por las condiciones pendientes de los clientes; no esperes cambios en Mobile todavía.
7. Para terminar la prueba sin dejar metadatos TheTVDB locales, usá **Revertir última recuperación en esta ficha**, revisá y guardá. Verificá que las publicaciones anteriores y `fecha_agregado` se mantengan. Si solo consultaste, cancelá sin aplicar; el catálogo no cambió.
8. Probar después una consulta TMDB/TVmaze confirma la navegación y el flujo existente. No realizar migraciones ni múltiples importaciones de producción como prueba inicial.

Para recompilar/firma en otro entorno, conservá el keystore original fuera del repositorio. Después ejecutá `apksigner verify --verbose --print-certs` y `aapt dump badging`. No pongas contraseñas en comandos guardados, Gradle, Git, informes ni capturas. Nunca generes otra clave suponiendo compatibilidad.
